🏗️ Arquitetura do Sistema e Engenharia de Software

Visão abrangente dos componentes de backend Spring Boot 3, interfaces React 18, modelagem relacional, máquina de estados rigorosa e controle triplo de estoque físico e reservado.

🏛️ Visão Geral da Arquitetura

O sistema foi desenhado segundo os preceitos de Arquitetura Limpa / Hexagonal (Ports & Adapters), dividindo-se em três pilares autônomos:

  • Backend RESTful: Spring Boot 3.4 (Java 21 LTS) com Spring Data JPA, Flyway para migrações imutáveis, banco H2 (arquivo local compatível com PostgreSQL) e validações com Bean Validation;
  • Frontend SPA / PWA Ready: React 18 com TypeScript, Vite, Tailwind CSS, Radix UI e Lucide Icons, entregando interfaces responsivas para vendas de campo (mobile) e backoffice fiscal (desktop);
  • Módulo Satélite de Estoque: Módulo Python local offline para manipulação de XMLs de NF-e e atualização da planilha Excel com backups automáticos.

🔄 Máquina de Estados e Controle Triplo de Estoque

O sistema implementa o padrão de Estoque Triplo por SKU, evitando rupturas ou vendas além do estoque disponível no galpão:

📐 Equação Fundamental do Estoque

availableStock = physicalStock − reservedStock

⚡ Integrações Externas

1. BrasilAPI (Enriquecimento Cadastral Instantâneo)

A API de Backoffice consulta a BrasilAPI de forma síncrona:

  • Consulta de CNPJ: GET https://brasilapi.com.br/api/cnpj/v1/{cnpj} — preenche Razão Social, Fantasia, CNAE, Endereço e Situação Cadastral;
  • Resolução de Código IBGE: GET https://brasilapi.com.br/api/ibge/municipios/v1/{uf} — obtém o código IBGE oficial de 7 dígitos (ex: 3550308 para São Paulo), exigência indispensável da SEFAZ SP.

2. Gerador Fiscal NF-e 4.00 (FocusNfeSimulatorAdapter)

Calcula a chave de acesso oficial de 44 dígitos aplicando o algoritmo do dígito verificador módulo 11 conforme o Manual de Orientação do Contribuinte (MOC): 

Chave = UF(35) + AAMM(2610) + CNPJ(09265201000195) + Mod(55) + Série(001) + nNF(000012377) + tpEmis(1) + cNF(10042002) + cDV(1)
